Fase 1 — Preparar o VPS
Docker, Docker Compose, firewall, DNS
Acessar VPS via SSH
~2 min
▾
ssh root@SEU_IP_HOSTINGER

Use a senha ou chave SSH que a Hostinger forneceu. Se for a primeira vez, aceite o fingerprint.

Instalar Docker + Docker Compose
~5 min
▾
# Atualizar sistema apt update && apt upgrade -y # Instalar Docker curl -fsSL https://get.docker.com | sh # Verificar instalação docker --version docker compose version

O script oficial do Docker já instala o Compose plugin (v2). Se docker compose version funcionar, está tudo certo.

Configurar firewall (UFW)
~2 min
▾
ufw allow 22/tcp # SSH ufw allow 80/tcp # HTTP ufw allow 443/tcp # HTTPS ufw enable ufw status
⚠️ NÃO abra portas 4000 (API), 5432 (Postgres), 6379 (Redis), 5678 (n8n). Esses serviços ficam APENAS na rede interna Docker.
Apontar DNS para o VPS
~5 min (propagação pode levar até 24h)
▾

No painel do seu registrador de domínio, criar registros A:

app.orinjoias.com.br → A → SEU_IP_VPS api.orinjoias.com.br → A → SEU_IP_VPS

Ou, se usar subdomínio único:

orion.orinjoias.com.br → A → SEU_IP_VPS
ℹ️ Verifique propagação: dig +short app.orinjoias.com.br deve retornar seu IP.
🚀
Fase 2 — Deploy do ORION CRM
Clone, .env, build, migrations, SSL
Clonar repositório
~2 min
▾
mkdir -p /opt && cd /opt git clone https://github.com/SEU_USER/Orion-CRM.git orion cd orion
Criar e preencher .env
~10 min
▾
cp .env.example .env nano .env

Gerar os secrets:

# JWT_SECRET openssl rand -hex 64 # JWT_REFRESH_SECRET (diferente do anterior!) openssl rand -hex 64 # OPERATOR_WEBHOOK_SECRET openssl rand -hex 32 # POSTGRES_PASSWORD openssl rand -hex 24 # UAZAPI_WEBHOOK_PATH (path secreto do webhook) openssl rand -hex 16

Variáveis obrigatórias para preencher no .env:

# Core NODE_ENV=production POSTGRES_PASSWORD=(gerado acima) DATABASE_URL=postgres://orion:SUA_SENHA@postgres:5432/orion_db REDIS_URL=redis://redis:6379 JWT_SECRET=(gerado acima) JWT_REFRESH_SECRET=(gerado acima) OPERATOR_WEBHOOK_SECRET=(gerado acima) # URLs (ajustar para seu domínio) APP_URL=https://orion.orinjoias.com.br FRONTEND_URL=https://orion.orinjoias.com.br # uazapi UAZAPI_SERVER_URL=https://free.uazapi.com UAZAPI_INSTANCE_TOKEN=(token da instância uazapi) UAZAPI_WEBHOOK_PATH=(gerado acima) # OpenAI OPENAI_API_KEY=sk-... # Mercado Pago (se já tiver) MP_ACCESS_TOKEN= MP_WEBHOOK_SECRET= # n8n N8N_API_KEY=(openssl rand -hex 32)
⚠️ NUNCA commitar o .env no git. Confirme que está no .gitignore.
Build e subir containers
~5-10 min (primeiro build)
▾
# Validar compose docker compose config # Build e subir tudo docker compose up -d --build # Verificar se todos estão healthy docker compose ps

Todos os serviços devem aparecer como Up ou healthy. Se algum estiver restarting, checar logs:

docker compose logs api --tail=50 docker compose logs postgres --tail=50
Verificar health check
~1 min
▾
curl http://localhost/health
✅ Resposta esperada: {"status":"ok","db":"ok","redis":"ok"}

Se db ou redis estiverem "error", verificar as variáveis DATABASE_URL e REDIS_URL no .env.

Configurar SSL (Let's Encrypt)
~10 min
▾
# Instalar certbot apt install certbot -y # Parar nginx temporariamente para gerar cert docker compose stop nginx # Gerar certificado (ajuste o domínio) certbot certonly --standalone -d orion.orinjoias.com.br # Copiar certs para o nginx cp /etc/letsencrypt/live/orion.orinjoias.com.br/fullchain.pem nginx/ssl/ cp /etc/letsencrypt/live/orion.orinjoias.com.br/privkey.pem nginx/ssl/

Depois, editar nginx/nginx.conf: descomentar os blocos SSL, ativar redirect 80→443, e reiniciar:

docker compose up -d nginx
ℹ️ Configurar renovação automática: crontab -e → adicionar 0 3 1 * * certbot renew --post-hook "docker compose -f /opt/orion/docker-compose.yml restart nginx"
Provisionar admin (primeiro usuário)
~2 min
▾

Chamar o webhook de provisioning para criar o primeiro admin:

# Gerar HMAC da assinatura BODY='{"action":"provision","idempotency_key":"init-001","payload":{"admin":{"name":"Guilherme","email":"seu@email.com","password":"SenhaForte123!"},"branding":{"company_name":"ORIN Joias","primary_color":"#C8A97A"},"plan":{"type":"professional"}}}' SIG=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "SEU_OPERATOR_WEBHOOK_SECRET" | awk '{print $2}') curl -X POST http://localhost/api/v1/operator/webhook \ -H "Content-Type: application/json" \ -H "X-Operator-Signature: $SIG" \ -d "$BODY"
✅ Esperado: {"result":"success"} → Agora você consegue logar no CRM com o email/senha definidos.
Testar login no CRM
~1 min
▾

Abrir https://orion.orinjoias.com.br/login no navegador e logar com as credenciais do admin criado acima.

✅ Se o dashboard carregou, o CRM está operacional.

Fase 3 — Configurar n8n
Acessar, criar credenciais, importar workflow
Verificar n8n no docker-compose.yml
~5 min
▾

O n8n precisa estar definido como service no docker-compose.yml. Se ainda não estiver, adicionar:

# Adicionar ao docker-compose.yml n8n: image: n8nio/n8n:latest restart: unless-stopped ports: - "127.0.0.1:5678:5678" # Só localhost — não expor publicamente environment: - N8N_HOST=0.0.0.0 - N8N_PORT=5678 - N8N_PROTOCOL=https - WEBHOOK_URL=https://orion.orinjoias.com.br - GENERIC_TIMEZONE=America/Sao_Paulo - N8N_ENCRYPTION_KEY=$(openssl rand -hex 32) volumes: - n8n_data:/home/node/.n8n networks: - app_network depends_on: - api # Adicionar no bloco volumes: do compose volumes: n8n_data:
⚠️ Sem o service n8n no compose, nada funciona. O ports: "127.0.0.1:5678:5678" garante que o editor só é acessível localmente (via SSH tunnel). A variável N8N_ENCRYPTION_KEY deve ser gerada uma vez e guardada — se mudar, todas as credenciais salvas são perdidas.

Subir o container:

docker compose up -d n8n

Confirmar que está rodando:

docker compose ps n8n
✅ Esperado: n8n Up 0.0.0.0:5678->5678/tcp
Acessar n8n via SSH tunnel
~2 min
▾

O n8n NÃO está exposto publicamente (segurança). Acesse via túnel SSH:

# No seu computador local (não no VPS) ssh -L 5678:localhost:5678 root@SEU_IP_HOSTINGER

Agora abra no navegador: http://localhost:5678

Na primeira vez, o n8n vai pedir para criar uma conta de admin. Use senha forte.

Criar credencial: API ORION
~2 min
▾

No n8n: Settings → Credentials → Add Credential

Tipo: Header Auth

Name: ORION API Header: Authorization Value: Bearer SEU_N8N_API_KEY_DO_ENV

Salvar. Essa credencial é usada em todos os nós que chamam a API do ORION.

Criar credencial: uazapi
~2 min
▾

Tipo: Header Auth

Name: uazapi WhatsApp Header: token Value: SEU_INSTANCE_TOKEN_UAZAPI
⚠️ Use o token NOVO (rotacionado). Não use o que foi exposto na conversa anterior.
Criar credencial: OpenAI
~1 min
▾

Tipo: Header Auth (o workflow usa HTTP Request direto para a API OpenAI)

Name: OpenAI ORION Header: Authorization Value: Bearer sk-SUA_OPENAI_API_KEY
ℹ️ Usamos Header Auth (não o nó nativo OpenAI) para ter controle total sobre response_format: json_object e parâmetros do modelo.
Configurar variáveis de ambiente no n8n
~3 min
▾

Editar o docker-compose.yml no VPS e adicionar as variáveis ao service n8n:

# Adicionar ao environment do n8n no docker-compose.yml # ⚠️ OBRIGATÓRIO: sem WEBHOOK_URL, os webhooks geram URL interna WEBHOOK_URL: https://orion.orinjoias.com.br N8N_HOST: 0.0.0.0 N8N_PORT: 5678 N8N_PROTOCOL: https GENERIC_TIMEZONE: America/Sao_Paulo # Variáveis do workflow do chatbot UAZAPI_SERVER_URL: https://free.uazapi.com ORION_API_URL: http://api:4000/api/v1 ATENDENTE_WHATSAPP: 5521999999999 CATALOGO_URL: https://orinjoias.com.br/catalogo INSTAGRAM_URL: https://instagram.com/orinjoias
⚠️ WEBHOOK_URL é obrigatório. Sem ele, a Production URL do webhook vai mostrar http://localhost:5678/... em vez do domínio público. A uazapi não conseguirá entregar mensagens.

Depois reiniciar o n8n:

docker compose up -d n8n
Importar workflow do chatbot
~2 min
▾

No n8n: Workflows → Import from File → selecionar o arquivo ORION-WF-Bot-Qualificacao-WhatsApp.json

Após importar, abrir o workflow e:

1. Vincular credenciais — clicar em cada nó HTTP Request e selecionar a credencial correspondente:

Nós com "API" no nome → credencial ORION API Nós com "uazapi" ou envio → credencial uazapi WhatsApp Nó "OpenAI Qualificação" → credencial OpenAI ORION

2. Verificar URLs — conferir que os nós apontam para http://api:4000/api/v1/... (rede Docker interna)

3. NÃO ativar ainda — primeiro testar manualmente na Fase 5

📱
Fase 4 — Conectar uazapi + Webhook
Configurar webhook da uazapi para apontar pro n8n
Copiar URL do webhook do n8n
~1 min
▾

No workflow importado, clicar no nó Webhook (primeiro nó). O n8n mostra duas URLs:

• Test URL: funciona só com workflow aberto no editor (para debug)

• Production URL: funciona quando o workflow está ativado

Copiar a Production URL. Vai ser algo como:

https://orion.orinjoias.com.br/webhook/XXXXXXXX
⚠️ Mas espera — o n8n não está exposto publicamente! O webhook precisa ser acessível pela uazapi (externa). Vamos resolver no próximo passo.
Expor webhook do n8n via NGINX (rota específica)
~5 min
▾

Adicionar no nginx/nginx.conf uma rota APENAS para o webhook, usando o path secreto:

# Dentro do bloco server {} no nginx.conf # Apenas a rota do webhook é exposta — NÃO o editor do n8n location /webhook/ { proxy_pass http://n8n:5678/webhook/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_read_timeout 10s; }

Reiniciar nginx:

docker compose restart nginx

Agora a URL do webhook fica:

https://orion.orinjoias.com.br/webhook/ID_DO_WEBHOOK_N8N
ℹ️ O editor do n8n continua inacessível pela internet — só via SSH tunnel. Apenas /webhook/* é público.
Configurar webhook na uazapi
~2 min
▾

No painel da uazapi (free.uazapi.com), acessar sua instância e configurar o webhook:

# Via API da uazapi curl -X POST https://free.uazapi.com/setWebhook \ -H "Content-Type: application/json" \ -H "token: SEU_INSTANCE_TOKEN" \ -d '{ "webhookUrl": "https://orion.orinjoias.com.br/webhook/ID_DO_WEBHOOK_N8N", "events": ["message"] }'

Ou configurar via painel web da uazapi se disponível.

Verificar conexão WhatsApp
~1 min
▾
curl -s https://free.uazapi.com/status \ -H "token: SEU_INSTANCE_TOKEN" | jq .
✅ Esperado: {"connected": true, "number": "351931941768"}

Se connected: false, escanear QR code novamente no painel da uazapi.

Rotacionar token da uazapi (se vazou)
~3 min
▾

Se o token da instância foi exposto em logs, chats, ou código versionado, rotacionar imediatamente:

Opção A — Painel Web:

1. Acessar free.uazapi.com → sua instância → Settings

2. Clicar em Regenerate Token (ou equivalente)

3. Copiar o novo token

Opção B — Via API (se disponível):

curl -X POST https://free.uazapi.com/regenerateToken \ -H "token: SEU_TOKEN_ATUAL" \ -H "Content-Type: application/json"

Após rotacionar, atualizar em 2 lugares:

1. n8n: Settings → Credentials → uazapi WhatsApp → atualizar o Value com novo token

2. docker-compose.yml: se o token estiver em variável de ambiente, atualizar e docker compose up -d n8n

⚠️ O token antigo para de funcionar imediatamente. Se esquecer de atualizar no n8n, o chatbot vai parar de enviar mensagens.

~1 min

Após enviar a mensagem de teste, abrir o CRM (https://orion.orinjoias.com.br) e verificar:

• Inbox → conversa apareceu?

Ativar workflow no n8n
~1 min
▾

No n8n, alternar o toggle Active do workflow para ON.

A partir de agora, toda mensagem que chegar no WhatsApp será processada automaticamente.

ℹ️ Monitorar as primeiras horas: docker compose logs n8n --tail=100 -f
Configurar Error Workflow (monitoramento)
~5 min
▾

Criar um workflow auxiliar no n8n que recebe alertas quando qualquer workflow falha:

1. Criar workflow "Alerta de Erros":

• Trigger: Error Trigger (nó nativo do n8n)

• Ação: HTTP Request → enviar mensagem via uazapi para o número do atendente

# Body do nó HTTP Request (envio via uazapi) { "number": "{{ $env.ATENDENTE_WHATSAPP }}", "text": "🚨 ALERTA ORION\n\nWorkflow falhou: {{ $json.workflow.name }}\nErro: {{ $json.execution.error.message }}\nHora: {{ $now.toFormat('dd/MM HH:mm') }}\n\nVerificar no n8n." }

2. Ativar o workflow de alertas e copiar seu ID.

3. Vincular ao workflow principal:

• No n8n: Settings → Workflows → selecionar o workflow do chatbot

• Em Error Workflow, selecionar "Alerta de Erros"

ℹ️ Assim, se o chatbot parar de funcionar (API fora, OpenAI falhando, credencial expirada), você recebe imediatamente um WhatsApp avisando.
Warm-up do número WhatsApp
~2 semanas
▾

Números novos que enviam muitas mensagens automatizadas podem ser banidos pelo WhatsApp. Siga este cronograma gradual:

Semana 1:

• Máx. 20 conversas/dia

• Responda manualmente quando possível (mistura bot + humano)

• Não envie mensagens para números que nunca falaram com você

Semana 2:

• Máx. 50 conversas/dia

• Bot pode operar sozinho, mas monitore reports de spam

Semana 3+:

• Volume normal, sem limite artificial

• Manter anti-loop ativo (já configurado no workflow: 10+ msgs → handoff)

⚠️ Sinais de perigo: se clientes reportarem a mensagem como spam, ou se o número "cair" da uazapi (desconectar sozinho), pausar IMEDIATAMENTE o bot e investigar. O número pode ser suspenso temporariamente (24h) ou permanentemente.

Boas práticas permanentes:

• Sempre responder a mensagens iniciadas PELO CLIENTE (não cold outreach)

• Manter respostas naturais e personalizadas (o system prompt da IA já faz isso)

• Oferecer opção de "falar com humano" (handoff já configurado)

• Nunca enviar listas de broadcast ou mensagens em massa

Configurar backup automático
~5 min
▾
# Criar script de backup cat > /opt/orion/scripts/backup.sh << 'EOF' #!/bin/bash set -euo pipefail DATE=$(date +%Y%m%d_%H%M%S) BACKUP_DIR="/opt/orion/backups" mkdir -p $BACKUP_DIR docker compose -f /opt/orion/docker-compose.yml exec -T postgres \ pg_dump -U orion orion_db | gzip > "$BACKUP_DIR/orion_${DATE}.sql.gz" find $BACKUP_DIR -name "*.sql.gz" -mtime +30 -delete echo "Backup done: orion_${DATE}.sql.gz" EOF chmod +x /opt/orion/scripts/backup.sh # Agendar diário às 2h (crontab -l 2>/dev/null; echo "0 2 * * * /opt/orion/scripts/backup.sh >> /var/log/orion-backup.log 2>&1") | crontab -
